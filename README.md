# A股抄底/潜伏多维技术分析 Skill (stock-bottom-fishing)

输入股票**名称或代码**，一键完成 **18 个主维度 + 7 个补充维度**的技术体检；也支持**多只持仓横向体检**、**MACD 金叉专题推演**与**逃顶/止盈评估**，输出结构化、可套用固定模版的结论。

## 能力

| 场景 | 你会得到 |
|---|---|
| "XX 能不能抄底 / 见底了吗 / 适合潜伏吗" | 18 维体检 + 7 维补充（BBI/TRIX/ROC/VR/MFI/AR·BR/XSII）+ 四档结论（强势买点 / 左侧潜伏区 / 等待区 / 不适合）+ 触发清单 + 止损 |
| "我这几只持仓怎么处理" | 大盘快照 + 横向对比表 + 风险标签 + 逐只处置与纪律提示 |
| "MACD 金叉了会不会反弹 / 什么时候金叉" | 金叉路径模拟（何时、何价、需涨多少）+ 该股自身历史同类信号的胜率与中位收益 |
| "该不该卖 / 到顶了吗 / 还能拿吗 / 止盈位设多少" | 顶部信号块（超买标签 / SAR / 距高点回撤 / 0轴上死叉）+ 顶背离（摆动高点口径）+ 顶部四档镜像结论 + 分批止盈触发器与执行价 |

## 分析维度

| 类别 | 指标 |
|---|---|
| 超跌信号 | TD 神奇九转（绿9/红9、计数延长）、BIAS 乖离率、位置（距 60/250 日高低） |
| 动能指标 | MACD(12,26,9)、KDJ(9,3,3)、RSI(6/12/24)、WR(14)、CCI(14) |
| 趋势指标 | DMI/ADX(14)、均线系统(MA5/10/20/60/120/250)、BOLL(20,2) |
| 量能与资金 | OBV、量比(5日/20日)、主力资金流(当日/5日/10日净额)、筹码分布(获利比例/平均成本/90%·70%成本区) |
| 多周期 | 日线 + 周线 MACD/KDJ 共振、MACD 底背离（摆动低点口径）与**顶背离（摆动高点口径）** |
| 风险度量 | ATR(14) 日均波幅（用于止损距离）、关键支撑/压力由近及远排序、**SAR 抛物线转向（移动止损/止盈线，通达信口径）** |
| **补充维度（19~25）** | BBI 多空分水岭、TRIX(12)+TRMA、ROC(12)+MAROC、VR(26)、MFI(14)、AR(26)/BR(26)、XSII 薛斯通道 |

> 补充维度**只做加权、不单独定档**：与主维度同向时加分，矛盾时以主维度（资金/趋势）为准并把矛盾写进风险证据。取舍理由见 `references/mytt-merge-plan.md`。

## 核心思路

1. **三层漏斗定序**：先判位置 → 再判趋势 → 再判动能与资金 → 最后落到价位。同一根绿9，低位是机会、半山腰是陷阱。
2. **信号是统计事件，不是买入指令**。判"金叉会不会涨"用该股自身历史同类信号的中位收益/胜率/再死叉率定价，不套用直觉。
3. **量化等待成本**。不说"等金叉"，说清"明日金叉需涨 20.3%（对照 ATR 不可能）；横盘则第 11 日、+1%/日则第 5 日"。
4. **量能可以放大也可以证伪信号**，极度缩量下的上涨不构成确认。
5. **绿9 是转折预警，不是买入指令**。可靠买点 = 绿9 + 次日/近期放量阳线确认（TD 9 后买阳不买阴）；极弱趋势中绿9 后常延长，裸绿9 视为下跌中继。
6. **纪律高于预测**：每个结论必须落一个具体止损数字（= 最近有效支撑 − 1×ATR）。
7. **指标口径原语化**：TD 九转、MACD 金叉/死叉、摆动低点/高点背离全部由通达信原语（`t_*`，移植自 MyTT）计算，上层脚本只渲染不手写判定，保证多脚本对同一只票结论一致。
8. **数据层自带韧性**：本地缓存 + 限流冷却 + 等待预算 + 主机熔断 + 分档限速，冷启动 ≈8s、四脚本连跑 ≈12s 且不再偶发失败。数据降级时**照标注出报告，不反复重跑**。
9. **逃顶是抄底的镜像，不是另一套框架**：把三层漏斗上下颠倒着用 —— 胜率→跌率、触 MA20→破 MA20、再死叉→再金叉、底背离→顶背离、买阳不买阴→**卖阴不卖阳**。**超买标签只做"减仓保护"、不做"清仓判顶"**；SAR 是事前约定的移动止盈线，收盘跌破即执行。买入建议与止盈触发器必须成对出现。

完整版见 `references/playbook.md`。

## 安装

把本目录复制到你的 Trae 工作区：

```bash
mkdir -p <workspace>/.trae/skills
cp -r stock-bottom-fishing <workspace>/.trae/skills/
```

安装依赖（**不需要 akshare**）：

```bash
pip install requests pandas numpy --break-system-packages
```

> 本技能所有请求都在 `stock_lib.py` 里主动清除系统代理并 `trust_env=False`，
> 因此在需要走内网代理的环境下也能直连东财/腾讯。若你的网络必须走代理，
> 请自行调整 `stock_lib.py` 顶部的代理处理逻辑。

## 使用

在 Trae 中直接说"分析 XX 能否抄底"，或手动运行：

```bash
# 单只 18 维 + 7 维补充体检
python3 scripts/analyze_stock.py 002552        # 代码
python3 scripts/analyze_stock.py 宝鼎科技       # 名称亦可
python3 scripts/analyze_stock.py 512480 --no-flow   # ETF / 跳过资金流
python3 scripts/analyze_stock.py 002552 --no-chip   # 跳过筹码（更快）

# 持仓 / 多标的横向体检
python3 scripts/holdings_check.py 002552 603330
python3 scripts/holdings_check.py 002552:51.2 603330:9.8     # 代码:成本
python3 scripts/holdings_check.py 002552:51.2:200            # 代码:成本:股数
python3 scripts/holdings_check.py --file holdings.txt        # 每行 代码,成本,股数
python3 scripts/holdings_check.py 002552 603330 --detail     # 附单只全文

# MACD 金叉专题（两脚本联用）
python3 scripts/macd_path.py 002580 --days 15
python3 scripts/macd_stats.py 002580 --start 20220101 --horizon 10

# 逃顶 / 止盈专题（同一脚本切换方向）
python3 scripts/macd_stats.py 002552 --side top        # 0轴上死叉 + TD红9 两套顶部口径
python3 scripts/analyze_stock.py 002552                # 输出 [顶部信号] 区块（含 SAR）

# 数据层自检
python3 scripts/stock_lib.py 002552
```

## 输出内容

- 实时行情快照（价格/涨跌幅/量比/换手/主力净额与占比/5日·10日主力）
- TD 九转近 12 日序列（标注绿9/红9、是否延长、距上次 9 的天数）
- 日线全指标 + 补充维度（BBI/TRIX/ROC/VR/MFI/AR·BR/XSII）+ 60 日位置 + 周线共振 + 主力资金流 + 筹码分布
- 底部背离明细：摆动低点（日期/低点/DIF）与成色分档（柱是否同步抬高）
- **顶部信号块**：超买/顶部标签数、SAR 值与多头/空头持有期及翻转天数、距 60·250 日最高回撤、0 轴上死叉距今天数与样本内次数
- **顶部背离明细**：摆动高点（日期/高点/DIF）与成色分档（柱是否同步走低）
- 关键价位体系：支撑/压力由近及远 + 参考止损（最近支撑 − 1×ATR）
- 持仓模式额外输出：大盘快照、横向对比表、风险标签、处置提示
- 上层按 `references/report-template.md` 套模版，按 `references/playbook.md` 给出四档结论：
  强势买点（右侧确认）/ 左侧潜伏区 / 等待区 / 不适合（回避）；
  逃顶侧镜像四档为：顶部确认（理应离场）/ 顶部警示（减仓保护）/ 持仓观察 / 趋势健康（继续持有），
  并配套 SAR 移动止盈线、分批减仓价与 ATR 兜底价。

## 数据源与容错

**东财（首选，盘中含当日 K 线，带换手率）→ 腾讯（兜底，无换手率）→ 本地缓存** 自动回退，降级时在报告中明确标注（如 `[过期缓存,可能滞后]`）。数据层内置冷却、等待预算与主机熔断，**遇到限流会自动降级而不是无限重试**。

已固化的几个关键口径：

- 东财 K 线必须 `beg=0&end=20500101&lmt=<1600/800/500>`，写具体日期会连接被断
- 筹码**没有服务端接口**，由本地复刻东财前端 JS 算法（最近 210 根不复权日K + 换手率递归衰减 + 三角分布），获利比例为 0~1 小数
- 筹码依赖东财不复权日K；东财历史主机整段不可用时筹码会缺失（腾讯源无换手率），属**预期降级**，报告中如实标注即可
- 东财历史类接口有分档限速（3s/次），快照类走 1s；冷却最长 120s，闲置 180s 自动归零
- 报"日K所有数据源均失败"才是真故障（连缓存都没有），按 `references/troubleshooting.md` §八 排查网络与代理

详见 `references/troubleshooting.md`（含 §十 韧性机制的现场诊断与实测基准）。
